# Debug tool: game state and warps

`tools/debug/warp.lua` reaches every scene in `tools/debug/scenes.txt` from a cold boot (generated by
`tools/debug/gen_scenes.py`); `tools/debug/warp_all.py` runs them all in parallel and keeps one shot per scene.
No `--debugger` needed: every hook is a per-frame RAM read/write. **2026-11-01 correction:** each map now
runs its own initializer from the scene row. Earlier map tours used the world-map initializer and do not
prove NPC/decorative sprite coverage. See `map-initializers.md` for evidence and current reachability.

## RAM (verified by the warps below working)
| Address | Size | Meaning |
|---|---|---|
| 0x8008C490 | u8 | top-level mode; EXE switch 0x80020F40 (99 cases), overlay per mode from table 0x80018158. 0x46 title, 0x49 main menu, 0x4A continue, 0x50 trial-match pick (おためし対戦), 0x4D story start (intro event), 0x01 field (OVLGMAIN), 0x02-0x3D minigames (OVLM??) |
| 0x8008C4F9 | u8 | event number OVLEVT plays at mode 0x4D (0-37; 19 = opening, 20 = ending + credits). Written at the first frame of 0x4D |
| 0x8008C570 | u16 | current field map (0-363), index into the OVLGMAIN map table 0x800E78E4 (40-byte records; `tools/maps.py`) |
| 0x800BF7B8 | struct | script interpreter / message window: +0 running script (0 = idle), +4 next op address (while a message op runs, +4 walks its text instead), +0x44 current op |
| 0x800A3DE0 | 32 x 8 | loaded-file slots `{u32 base, u16 data id}` (`tools/fileids.py` names them) |

Interpreter loop: EXE 0x8003698C, `[sp+0x10]` = address of the next op (found with an exec hook; the per-frame
warp uses VM+4 instead).

## Script ops used (verified: the warp runs them)
- `0x1D map x y dir exit`: change map (all u16; `exit` 0xFFFF/0xFFFE). gen_scenes.py takes each map's commonest
  0x1D destination from the G*.BIN scripts as its arrival point.
- `0x1E 0x63`: the op every exit script ends with.
- `0x02`: message (inline block, text.md). 0x01 runs before the opening's first message.

## How each scene kind is reached (from a cold boot)
- **menu**: Start at the title from ~frame 2400, then the menu presses (circle/right) with the timings in warp.lua.
- **event N**: New game → いざ！物語へ; at mode 0x4D write N to 0x8008C4F9.
- **game MODE**: New game → おためし対戦; when the trial pick (0x50) hands over, overwrite the mode with MODE.
- **name_entry**: `game 0x51 3` uses that transition plus the native mode-context
  byte (`0x800A3F40 + mode`) so confirmation returns to Quick Match. The controller
  tour in `tools/debug/name_entry.py` covers all 80 character IDs, editing and
  the returned name bytes. See `name-entry-qa.md` for the exact state fields.
- **map M**: New game → story; at 0x4D set mode 1 (skips the intro; GMAIN then starts the opening script). When the
  script's next op is its first message (op 2), write `0x1D M x y dir 0xFFFE; 0x1E 0x63` over it, press circle,
  and restore the original words once both ran. A copy of the ops elsewhere in RAM hung (earlier exec-hook try).
- **save_menu**: use the same opening-script hijack, then the shrine's `2D 006A 0003 0000 0000; 2E; 03 0000; 00`
  sequence (GSV0101D entry 2). It enters mode 0x4B and reaches the file selector from a cold boot. Arrival is
  recorded 600 frames after that mode starts. Stop automatic message-closing circle presses outside mode 1:
  otherwise they select slot 1 and repeatedly accept the confirmation's default **No**.
  `SAVE_CONFIRM=true` presses circle at arrival+1500, up at +1800 and circle at +1920; `HOLD=6000` leaves time
  for the game to finish writing. `tools/debug/save_fixture.py` runs this with a copied empty card, checks for
  `BISLPM-86888-A` in an allocated directory entry and proves the seed card stayed unchanged.
- **Saved Status**: `tools/routes/status_saved.txt` with `--sav work/qa/save_fixture_checked/memcard1.mcd`.
  After loading the file and dismissing "Load complete", the game returns to the submenu; select Status again.
  Steps show question marks on the original too (the initial fixture has no pedometer).
- **Album enable flag**: EXE 0x800435F4 scans 70 records at **0x800BDBF0**, stride **0x1C**, for a nonzero first
  word. `tools/debug/records.lua --var RECORDS=true` marks only record 0 as played, in RAM. This enables album
  access for QA but does not manufacture a real score/rank or modify the original memory card.
  For complete record-panel coverage, `tools/debug/album_records.py` seeds ranks and scores after a real
  save load and navigates 43 Game Album pages or six Quick Match pages (`--trial`). `--empty` checks the
  no-record sentinel and `--original` supplies native comparisons. Exact fields and limits: `album-records-qa.md`.
- **Card Album**: `SCENE='card_album'` enables collectible bits 0-99 at **0x800BD9F8** and enters mode
  **0x4C** from the first intro-mode frame. Pair with `tools/debug/cards.lua`, `HOLD=-1` for all 100 pages.
  The probe verifies display index **0x800E2324** and state **0x800E232C**, and latches the cached Right input
  off after each page change to prevent CD-load skips. `tools/debug/cards_qa.py RUN --out DIR` requires every
  full illustration and caption to match its own TIM. Details and the original reference: `cards-qa.md`.

## Arrival points and historical hangs
**Mask Maker:** `SCENE='mask_editor'` calls the shop minigame from Story using `GSV1306D:2`'s op sequence
at 0x134 (`2D 46 2 1 0 2E 3 0 0`, u16). It retains a valid return context unlike direct `game_m70_3a`.
`tools/debug/masks.lua` selects six parts with controller input and verifies the confirmation state;
`masks-qa.md` records the read-only RAM synchronization addresses and cold original/English evidence.
The scene list now contains 464 entries after restoring the nine excluded maps below.

**Historical diagnosis, superseded by `map-initializers.md`:** warping to some maps at their commonest arrival point hung the emulator a few frames after the map's entry
script runs (frames stop, same under the interpreter; no CPU-exception pause event). `tools/debug/find_arrivals.py`
tried every other script destination and +-1..2 tile shifts: 25 maps work elsewhere (OVERRIDE in gen_scenes.py),
9 hung at every point and were commented out: 9 (GF0401), 29-31, 34 (GF12 rooms), 187, 201, 204, 294.
Tried and not the cause: exit word 0xFFFF vs 0xFFFE, the game's own fade-out op `0x1B 1 1 10` before 0x1D, and a
two-hop warp through a working map's entry script (the second 0x1D never loaded). Eight now pass with their
correct initializer; 294 also passes after preserving its normal entry's setup operations
(`map-initializers.md`). The other recorded overrides remain until rechecked.

Map 284 (GV2500): the en build never loaded it from (19,11) dir 2 (GSD0000D's destination; the VM stays on the
0x1D op, frames keep running, heap A only half used), while the original did. Not text or memory: reverting
single scripts did not help, only all GSV*+GSF0* together, and sector shifts of the map files flip it either way
(GV25000D at LBA 40649 ok, 40650 fails, 40666 ok): a CD-timing race in the warp. Dir 0 (GSF0000D's own entry,
the route the game uses) loaded in both builds at that checkpoint: OVERRIDE in gen_scenes.py.
**Reopened 2026-11-01:** direction 0 also fails repeatedly on the frozen card-prop
build, while the original and current Games-sign build pass. The VM remains on
op 001D despite the map-number variable changing to 284. `corrected-tour-qa.md`
records the exact builds, repeated cold cases and read-only `map_watch.lua`
trace. The layout/timing dependency remains unresolved; do not call dir 0 a
general fix or count a map-number change as completed loading.

**Later correction:** the bare warp reaches a SEQ tempo divide-by-zero at
8006D494 (Cause24), not a CD-loader wait. Map284 now preserves GSF0000D:23's
`59 2; 56 1D` before op1D and `57 0 0 1` before its initializer. Two cold runs
on each of original/frozen/current discs pass. `map284-regression.md` records
the negative fixture and remaining limits; no timing delay or game-code patch
was introduced.

`OPS={u16,...}` (warp.lua var) writes extra ops before the map change at the hijack, e.g. an op 26 caption from
`tools/debug/caption_ops.py ID`: the game's own caption handler draws it, then the map changes.

## Script ops: guesses for phase 4
- `0x1E N` after a 0x1D takes many values (0x63, 0x3FF, 0x1FA...): looks like a label/jump id, not a byte offset.
- `0x1B 1 1 10` precedes 427 of the 0x1D ops: fade out.
